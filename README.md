# A Face in the Crowd

A planned, local-first iPad app for naming people in personal photo collections and finding photos containing selected combinations of them.

**Status:** buildable iPadOS 17 source slice with folder selection, recursive JPEG previews, local face detection and resumable incremental reconciliation. People supports manual naming, correction, deliberate merge and undo with stable person IDs; Search separates confirmed and possible matches for Together and Any; Only remains confirmed and unresolved-safe. Backup export, validated restore, privacy controls and whole-catalog deletion are implemented. Scans persist face analysis once and reuse it across rescans and relaunch. People shows saved unnamed groups and named possible photos; Verify reviews the same saved membership without a toggle or rescan. Recognition qualification remains separate. Physical iPad compatibility, qualified recognition and full MVP acceptance require separate device and model evaluation.

## Product direction

- Read one user-selected external-drive root and its nested folders without changing originals.
- Keep human-confirmed identities separate from machine suggestions.
- Search for any selected set of people with Together, Any selected, and Only selected rules; Exclude is deferred.
- Store the catalog locally and make backup, restore, and export explicit.
- Design for accessible iPad use and truthful progress, uncertainty, and source availability.

The planned compatibility floor is iPadOS 17. Older test iPads establish compatibility; an M4 iPad Pro establishes target performance. The accepted UI is retained. Foreground indexing must show honest progress and resume after interruption. Optional OS 26/27 features are outside the core MVP.

## Delivery sequence

1. Prove external-drive access, reconnect, durable decisions, and a licensed local face model on target iPads.
2. Complete verification of the read-only catalog, naming, confirmed-person search, and recovery workflow.
3. Add optional local scene understanding and query assistance after the core people workflow is reliable.
4. Complete local testing before a limited TestFlight with the intended testers.

The source design packet and operational planning records are retained locally and are excluded from this public repository. Reference artwork and third-party model weights are not licensed by this repository's MIT license. No family photographs or biometric data should be committed.

Accepted previews and stable photo identities survive interrupted scans. Trusted unchanged revisions reuse prior work; ambiguous revisions receive cancellable integrity reads. Source failures preserve accepted data, and missing records are marked only after successful complete discovery. Regranting an unverifiable source requires confirmation.

The transactional SQLite catalog, checkpoints and bounded preview cache stay in the protected app container. Synthetic regression coverage includes interruption, source loss, stale generations, disk pressure and migration rollback. Headless checks verify target membership and compile the app and both test bundles without booting a simulator. These checks do not establish real-drive access, live Vision behavior, native UI usability or physical-device performance. [INVARIANTS.md](INVARIANTS.md) defines the system contract; [CHANGELOG.md](CHANGELOG.md) records human-facing changes.

Checked existing opens admit schema 3 or 4; unsupported versions identifiable before recovery are rejected without changing the file. A read-only probe that specifically needs hot-journal rollback admits only a supported SQLite database header before protection changes, lets SQLite restore committed bytes and names, and checks the restored schema again before migration or publication. This recovery restores committed state rather than preserving uncommitted database/journal bytes. Temporarily missing photos retain their saved vectors; per-photo analysis writes inspect only that photo and use a scalar count to enforce the retained 20,000-row budget. Completion and saved-group catch-up state require the pinned pipeline and current source. Schema 4 adds durable face-analysis storage with content, source and pipeline guards. Backup exports remove derived vectors and mark restored catalogs for recomputation while retaining human decisions. The core derives bounded provisional groups from a consistent durable-analysis snapshot, with stable seed identity across naming and later analysis. Naming a displayed conservative group assigns its label to every safe pinned member in one guarded, undoable transaction; the cover is the only new training anchor. Exclusions persist across reseeding, remove the corrected member's label when needed, and support guarded undo. Displayed-group deletion suppresses that content/source generation across model refresh and remains non-undoable. Scans persist analysis once and reuse it thereafter (see the face analysis boundary below); group naming and review UI are implemented; uncertain matches outside the pinned group remain available for Verify, and recognition qualification and owner acceptance remain separate.

## Manual identity boundary

Manual decisions attach to the selected current face generation. Distinct people may have equal display names; duplicate photo bytes and third-person assignments do not propagate during merge. The People workflow supports naming, reassignment, unsure, rejection, explicit not-a-person correction, and deliberate source-to-survivor merge. Every confirmed/rejected face conflict needs an exact explicit choice; cancel writes nothing. Merge and reopened undo restore links, negatives, deferrals, anchors, covers, names, source archive and distinct-photo counts atomically while advancing exemplar epochs. Legacy schema 3 undo payloads remain readable, and successive undo stays safe. An affected same-generation face unavailable at merge time must reconnect before merge; changed-generation history stays inactive.

People releases cached face-preview rasters and invalidates in-flight preview work when the view disappears or memory pressure is reported. DEBUG fixtures use explicit synthetic inputs and do not establish recognition. Native UI, physical-device and model qualification remain separate acceptance gates.

## Search and viewer boundary

Search captures confirmed results, grouping inputs, names and photo records in one SQLite read revision. Together and Any show separate confirmed and possible sections with independent immutable pages and counts. Only uses human-confirmed identities and withholds unresolved photos. Naming a pinned conservative group assigns the chosen person to every safe member, so all of those photos immediately appear as confirmed Search results; uncertainty outside the group remains available for Verify. Returning after a metadata decision refreshes both sections with the existing filters; paging retains its immutable capture. The explicit reviewed-group confirmation API still pins every inspected manual state and generation in one transaction; Undo restores the whole batch. The read-only viewer validates the selected original and falls back to a bounded cached preview when the original is unavailable or changed. Capture ordering uses validated original JPEG wall-clock metadata. These capabilities do not qualify recognition suggestions, backup/restore, physical-device behavior, or a production model.

## Face analysis boundary

During a scan, photos whose bytes were actually read may get face analysis: the scan reuses those exact bytes, runs the pinned local YuNet and SFace models on the CPU, and attaches raw vectors only to existing Vision face IDs that match one detection uniquely. Results persist in the protected catalog through a fenced transaction that rechecks the current source, content hash, geometry and detector generation, rechecks exact-generation suppression before inserting (so a deletion landing mid-flight cannot re-insert suppressed vectors), and prunes stale source-binding rows before capacity counting. Human naming during in-flight analysis does not discard usable model results; generation, source or session changes do.

Scans analyze once and reuse thereafter. A trusted unchanged photo whose current completed analysis matches the actual catalog photo, source binding and pipeline causes zero extra reads and zero model work across rescans and relaunch; durable vectors reload from the catalog after relaunch or memory pressure. A trusted unchanged photo missing analysis gets exactly one admitted catch-up read after the pinned models are prepared and thermal/memory admission is open; failed, paused and capacity-full states are explicit retry states, never empty success, and `CatalogRepository.admitFaceAnalysisRetry(photo:manifest:)` explicitly admits another attempt for the inspected photo; ordinary scans preserve the retry hold. Catch-up preserves the stored Vision face keys, geometry, content version and manual identity decisions without rerunning the detector. Naming or viewing a photo never starts source reads or inference. Failures leave accepted analysis and manual decisions unchanged. Synthetic DEBUG fixtures bypass the trained models. This does not establish recognition usefulness or physical-device qualification.

People opens an unnamed group's photos and names its cover in place, preserving the group seed and visible photos. The chosen label is assigned to every safe pinned member in one undoable action, with the cover as the only new anchor; uncertain faces outside the group remain review suggestions. Each group crop opens its matching photo in the existing read-only viewer; closing returns to the same group and name. Original loading happens only after that explicit photo action. Named details distinguish confirmed members from possible suggestions. “Not in this group” removes only that member's assignment to the displayed person and records the separation; Undo restores the assignment and group. One off-main saved-membership result feeds People and Verify, including after reopening; label save and navigation never read sources or run inference. Grouping runs at coalesced, logarithmic awaited scan boundaries and respects the model thermal/memory gate. People offers one “Finish face analysis” action for photos with no saved analysis status and current retryable failures. It runs a guarded pass over only the listed photos, reusing completed work, marking no other photo missing and leaving the saved scan checkpoint unchanged; a confirmed reconnect to a changed source runs the full scan instead. A no-details failure is shown as “Faces could not be matched automatically” and is not retried repeatedly; other failure reasons use fixed safe wording. Source selection and original-source confirmation stay in the same People flow, while the shared screen status shows progress and setup errors. The action is unavailable while analysis is paused or local face capacity is exhausted. Manual per-face naming remains available below groups. Analysis-incomplete or no-details records can remain after a completed scan. Finish face analysis does not qualify recognition accuracy.

Verify shows one saved suggestion at a time with the candidate, closest confirmed example and similarity. Yes, Not this person, Unsure and Not a person are ordinary undoable decisions guarded against cards that changed elsewhere; Skip lasts for the session. Thresholds are uncalibrated and recognition is not qualified. DEBUG synthetic source/detector fixtures persist fixed fictional vectors during their first ordinary scan; no suggestion toggle or Find face details pass is required.

## Verification and diagnostics

`tools/verify.sh app.services --headless` runs the actual AppServices backup-progress port, injected-root fixture isolation and SwiftPM-only registration contract. The existing AFITCApp module hosts these tests; the other 44 App-session UI ports remain future work.

Use `tools/verify.sh task7.8 --headless` for the affected whole-group labeling, guarded correction, Search, Undo, and App-service regressions with iPad compilation. `phase7 --headless` unions current task7.1–task7.8 coverage with phase6; `tools/verify.sh phase-group-owner` runs the six focused group, People/Search routing and Verify UI journeys plus the manifest contract check. Use `tools/verify.sh task3.3 --headless`, `task4.1 --headless`, `task4.capture-date --headless`, `task4.2 --headless`, and `task2.3-producer --headless` for focused checks; `tools/verify.sh phase3` and `phase4` run accumulated gates. `tools/verify.sh phase6 --headless` runs the accumulated phase's Core tests and iPad compile without the simulator UI suite; the pre-push hook uses it, and the full `phase6` UI gate runs at release milestones. Native phase gates run only the 10 UI journeys in `ui.journeys`; the 44 App-session UI checks in `ui.release` run with `tools/verify.sh phase-release-ui` before a release. `tools/verify.sh phase6` runs the accumulated gate and requires `AFITC_RUN_SFACE_MODEL_TESTS=1` with `AFITC_SFACE_MODEL_PATH` set to the verified local SFace artifact, since skipped selectors fail the gate. Task and phase selector mappings live in `tools/test-manifest.json`; the runner checks exact Xcode and SwiftPM membership, mapped selectors, and iPadOS 17 app/test compilation, and fails on missing or drifting mappings. Each run writes receipts and logs under `.logs/verification/`; these logs and `HISTORY.md` are local ignored evidence, not files distributed with the public repository. This command list is reproducible guidance, not a claim that every command was run.

The standalone physical iPad diagnostic is registered as `phase-live-analysis-probe` and is skipped by default. For the tested physical route, set `AFITC_LIVE_UI_PROBE=1` in the UI test target's `EnvironmentVariables` dictionary in the signed `.xctestrun` file; a shell-only environment variable is insufficient. Set `AFITC_LIVE_UI_OBSERVE_ONLY=1` in the same dictionary to suppress the optional Finish tap and sample an already-running scan for up to 90 seconds. The probe activates the installed app and reports only safe aggregate analysis counts, fixed message categories, scan phase and booleans. Otherwise, it may tap Finish once when enabled; it stops at a source picker or identity-confirmation prompt and never selects a folder or confirms source identity. The generic `tools/verify.sh phase-live-analysis-probe` simulator route intentionally fails on this device-only test's simulator skip and does not execute a live check. This diagnostic does not qualify recognition.

The accumulated native phase gate uses the task set configured for that phase in `tools/test-manifest.json`; native UI checks run at that gate. It compiles the app/test bundles and executes synthetic UI checks on a disposable iPad simulator. The gate requires the installed shared `simctl_gate_lib.sh` at `~/Documents/Projects/apple_developer/release_tools/templates/` (override with `AFITC_SIMCTL_GATE_LIB`). The helper owns device cleanup, clone cleanup and the shared Apple UI lock. Native tests disable Xcode verbose test diagnostics (`-collect-test-diagnostics never`) to avoid stalled post-test simulator diagnosis; runner logs and XCTest attachments remain available, and actual passing selectors, successful markers, exit status and the watchdog remain required. Headless checks never boot devices. Simulator evidence does not establish physical source/device acceptance.

Diagnostics accepts fixed event categories and aggregate nonnegative counts only. Warnings always write; debug events require `--debug`. Protected, backup-excluded diagnostics rotate at 64 KiB into at most three archives, in the app container. Names, paths, images, vectors and free-form errors have no logging API. Model weights, conversion products, private catalogs/vectors, SwiftPM caches and diagnostics are excluded from Git; the changelog remains public.

## Pinned local model resources

Existing invalid files are preserved, promotion never overwrites a destination, and per-model locks serialize acquisition. `--verify-only` performs offline checks (also run before Xcode builds). Models and notices are bundled as read-only resources; no App download is enabled.

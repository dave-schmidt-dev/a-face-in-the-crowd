## YuNet fixed-640 pixel preparation

`JPEGPreviewDecoder.canonicalRGB(_:)` uses the same bounded orientation-aware ImageIO decode as Vision and emits owned sRGB RGB8 rows. `YuNetRasterPreprocessor` rounds fit dimensions half-up, applies the OpenCV 4.10 `INTER_LINEAR` pixel-center mapping and optimized ARM vertical kernel, centers the zero-padded content, and packs raw-scale BGR float32 NCHW `[1, 3, 640, 640]`. Resize and packing are cancellable between rows and report completed-row progress. The fixed-point coefficients and optimized high-product/rounded-pack behavior follow the pinned [OpenCV 4.10 resize source](https://raw.githubusercontent.com/opencv/opencv/4.10.0/modules/imgproc/src/resize.cpp) and [ARM intrinsics](https://raw.githubusercontent.com/opencv/opencv/4.10.0/modules/core/include/opencv2/core/hal/intrin_neon.hpp).

`task2.yunet-pixelprep` covers generated orientation/channel/stride/cancellation cases and has an explicit opt-in exact comparison against the ten frozen canonical RGB, 640 RGB canvas and tensor references. Set `AFITC_YUNET640_REFERENCE_PATH` to the existing `.logs/verification/phase2.yunet640-reference` directory to run that comparison. On the recorded arm64 OpenCV 4.10 CPU reference, all ten canvases matched byte-for-byte, every NCHW float32 bit matched, and rounded geometry matched. Evidence is under `.logs/verification/phase2.yunet-pixelprep-sliceA/`; this is input-pixel parity only, with no YuNet or SFace session, recognition, identity-usefulness or device acceptance.

## Qualified production runtime and current-domain fence

AFITCRuntime implements pinned SFace CPU preparation and serialized inference, plus pinned YuNet CPU named-head execution. Child work drains before the parent checks cancellation and current provenance at the return boundary; a held completion callback cannot authorize a stale result. The isolated and integrated headless checks use generated inputs and actual pinned local artifacts, not personal photos. SFace nine-output and YuNet ten-input/120-head comparisons record measured nonexact CPU differences without an accepted cross-backend tolerance or identity threshold.

CatalogFacePipeline captures and validates owner identity, present source binding (including confirmed null), exact photo hash/version/provider metadata, complete detector/SQL face membership and manual state in one existing actor-owned read transaction. An optional anchor binds only its person/exemplar revision. Unrelated preview/name/checkpoint changes do not invalidate the fence. This is transaction-instant freshness, not durable permission for a later awaited or persisted effect; App admission and write-transaction guards require their own integration.

Generic YuNet mechanics and the actual artifact diagnostic remain separate task mappings. The actual comparison requires explicit opt-in and an independently pinned frozen reference root. App pipeline wiring, iOS trained sessions, physical device timing/protection, CoreML partition/ANE use, and recognition usefulness remain unaccepted. Declared model licenses and verified notices do not by themselves establish rollout approval.

## Transient scan-byte producer

`TransientFaceEmbeddingProducer` (AFITCRuntime) is the production composition used by the App through `FaceEmbeddingCoordinator` and the existing `startScan` entrypoint. It prepares the bundled pinned YuNet and SFace artifacts off the MainActor once per scan, then per accepted photo runs canonical RGB, fixed-640 BGR tensor, YuNet heads, decode and inverse geometry, unique Vision UUID association, SFace five-point crop and raw 128-value inference. Preparation failure is retained for the scan and reported as unavailable. Progress text names stages and face counts only.

`tools/verify.sh task2.3-producer --headless` runs the artifact-independent selectors with fake ORT sessions behind the production adapter and is part of phase6. `task2.3-producer-pipeline-diagnostic` is separate and excluded from phase6. It runs only with `AFITC_RUN_PRODUCER_PIPELINE_DIAGNOSTIC=1` plus `AFITC_PRODUCER_YUNET_MODEL_PATH`, `AFITC_PRODUCER_SFACE_MODEL_PATH`, `AFITC_PRODUCER_JPEG_PATH` and `AFITC_PRODUCER_DIAGNOSTIC_OUTPUT`. It uses an isolated temporary catalog, runs actual Vision once to establish face UUIDs, then the producer on the host CPU. It writes only counts, stage messages, unavailable reasons, model pins and composition source hashes to the output file; vectors and image data are not written or printed. The diagnostic is **UNRUN** until the root supplies an authorized local JPEG. It makes no tolerance, usefulness or identity claim and does not establish iOS trained execution or physical-device behavior.
